# 會議待詢問清單（2026-10-08 整理）

給下次與公司研發人員開會用。依「不問清楚就動不了」的程度排序；每題寫清楚為什麼要問、問到會解開什麼。已確認的事項不重列，見 `03_待確認事項.md`。

## A. 資料格式（最優先，決定下一步寫什麼程式）

| # | 問題 | 為什麼需要 | 問誰 |
|---|---|---|---|
| A1 | 目前有兩種 JSON：**動作描述句**（`Timestamp`／`Motion`／`Speed`／`fall`，見 `data/samples_fall/`）與**裝置事件**（`{"mode","event","trigger","userReply"}`，見 `data/samples_device_event/`）。雲端保存 7 天的是哪一種？兩者是轉換關係（裝置事件 → 描述句）還是分開存？ | 換算規則與事件格式 v1 要以哪一種為準；若描述句是由模型產生的文字，它就不是量測值，不能直接當事實 | 雷達負責人 |
| A2 | 7 天資料的實際存取方式：HTTPS 是什麼 API（網址、認證、查詢參數、分頁、回傳格式）？MQTT 的 broker、topic、QoS、payload 格式？ | 寫讀取程式的第一步 | 雷達負責人、雲端負責人 |
| A3 | 裝置事件的 `event` 完整清單（目前見到 absence；另提過 moving、longstay、vacant、fall）、`trigger` 清單、`mode` 清單、`userReply` 的定義（是語音確認的回應嗎？false 代表沒回應還是回答「沒事」？） | 事件格式 v1 的列舉值；跌倒次數怎麼算 | 雷達負責人 |
| A4 | 裝置事件沒有時間戳，是雲端收到時補的嗎？用什麼時區與格式？描述句的 `Timestamp` 是本地時間無時區，是哪個時區？ | 7 天視窗、週報切週、跨日統計都靠它 | 雷達負責人、雲端負責人 |
| A5 | 有沒有事件編號、裝置編號、長者代號？一台裝置對應一位長者嗎（多人房怎麼辦）？ | 原則 3「每一筆追得回來」；個人層級的建議要能分到人 | 雷達負責人、甲方 |
| A6 | 有沒有任何欄位能算出**動作持續時間**（事件的開始／結束，或連續狀態的起訖）？ | 活動量目前只能算事件數；多數知識圖譜指標（坐站次數、步速、單腳站秒數）都需要時間或距離 | 雷達負責人 |
| A7 | 有沒有信心值？雷達能不能給任何數值量（步速、位移距離、起身用時）？ | 決定哪些指標能由規則算、哪些只能標「無法評估」 | 雷達負責人 |
| A8 | 資料量：每台裝置每天大約幾筆？ | Jetson 上的處理量與儲存 | 雷達負責人 |
| A9 | 格式改版怎麼通知、有沒有版本欄位？（待確認第 10 項尾巴） | 事件接收要能拒收未知格式 | 雙方 |
| A10 | 能否提供一週完整的真實（去識別）資料供開發與測試？ | 目前只有 1 天 11 筆與 1 筆裝置事件，寫不出週報 | 雷達負責人、甲方 |
