# 流程圖（2026-10-23）

把 `02_目標架構.md`、`16_Dashboard對接說明.md` 與 `src/radar_agent/` 現在的狀態畫成三張圖：全系統的兩條路、第一階段 Jetson 與 Dashboard 的交換、本 repo 內部從紀錄到文字的步驟。這裡只是整理，不是新的決定；內容有出入時以原文件為準，改了流程要同步更新這份。

圖例：綠色是本 repo，灰色是現有系統或其他團隊，紅色是即時警示路徑或停止輸出，虛線是還沒定案或還沒接上。

## 1. 全系統：兩條路分開

跌倒警示走秒級的即時路徑，不經過知識圖譜、LLM，也不經過本 repo（`adr/0006`）。分析建議路徑的等級由規則與知識圖譜決定，在地模型只改寫說法（`02_目標架構.md` 原則 2）。

```mermaid
flowchart LR
  DEV["雷達裝置<br/>偵測姿態、跌倒<br/>裝置端語音確認"]

  subgraph RT["即時警示路徑（不經本 repo）"]
    direction LR
    ALS["警示服務（雲端）<br/>多通道通知、逾時升級<br/>監看裝置心跳"]
    STAFF["居服員／家屬／機構<br/>按「已收到」"]
    ALS --> STAFF
  end

  subgraph UP["現有系統"]
    CLOUD[("雲端<br/>保存 7 天裝置事件")]
    JET["Jetson PC<br/>radarLLM：點雲 → 描述句"]
  end

  subgraph REPO["本 repo（正式部署跑在 Jetson）"]
    direction TB
    EV["事件整理<br/>格式檢查、造訪、在線時段"]
    RULE["規則評分<br/>量測值 → 等級"]
    KG[("知識圖譜 v1<br/>已核准版本")]
    TXT["依 Profile 產生文字<br/>範本 → 在地模型"]
    CHK{"輸出檢查<br/>數字、用語、讀者權限"}
    EV --> RULE --> TXT --> CHK
    KG -. 門檻與建議 .-> RULE
  end

  DASH["Dashboard（官網）<br/>呈現報告、甲方週報"]
  REVIEW["審核佇列<br/>候選等級、未通過的輸出"]

  DEV -- 跌倒預警 --> ALS
  DEV -- 裝置事件 --> CLOUD
  DEV -- "點雲＋裝置事件（MQTT，A32）" --> JET
  CLOUD -. 第一階段：經 Dashboard .-> DASH
  JET -. 正式部署 .-> EV
  DASH -- "JSON 紀錄" --> EV
  CHK -- 通過 --> DASH
  CHK -- 不通過 --> REVIEW

  classDef repo fill:#e3f1ee,stroke:#1d6b5f,color:#12302b

```

- 主要輸入是裝置事件；radarLLM 描述句只當補充，不拿來計數或判定（`adr/0001`）。
- 本 repo 不接收音訊（`adr/0005`），不讀雷達點雲本身。
- 甲方週報（跌倒次數、活動量）由 Dashboard 自己統計（`adr/0004`）。

## 2. 第一階段：Jetson 與 Dashboard 的交換

2026-10-23 確定：Demo 期間由 Dashboard 提供 JSON，暫時不從 Jetson 直接收 MQTT。先用三天內的資料，只做居服員的內容（`16_Dashboard對接說明.md`「第一階段的流程」）。下圖的請求與回應欄位是 API 草案，還沒和 Dashboard 約定。

```mermaid
sequenceDiagram
  autonumber
  participant J as Jetson（本 repo）
  participant D as Dashboard
  participant C as 居服員

  J->>D: 要資料：裝置、from、to（API 草案，未約定）
  D-->>J: 紀錄 JSON（records、settings、received_until）
  Note over J: radar-caregiver --json --from --to<br/>整理事件 → 產生文字 → 輸出檢查
  alt 輸出檢查通過
    J->>D: caregiver-report-v0（文字已檢查）
    D->>C: 照原文顯示：Alerts 放處置提示<br/>裝置卡片放事件摘要＋資料到幾點
  else 沒通過（結束碼 1）
    J--xD: 不輸出任何文字
  end
```

待確認：

- Jetson 怎麼向 Dashboard 要資料：網址、認證、參數、更新頻率（`16_Dashboard對接說明.md` 清單 4-1）。
- 單向門，要人決定：`counts` 要能表示「無法判斷」，回傳要附資料到哪裡為止。
- 警報沒開時報告怎麼寫，要先拿到 `settings`（A52）。
- Radar60FL 的格式目前讀不懂，欄位意思確認前不寫轉換程式（A45–A50）。
- 「警報已解除」要不要列在 Alerts，待和 Dashboard 負責人確認。

## 3. 本 repo 內部：從紀錄到文字

三個命令列入口共用同一段事件整理與輸出檢查。文字一律先由範本產生；接上在地模型後，模型的輸出也要過同一個檢查，沒過就退回範本。

```mermaid
flowchart TB
  IN[/"紀錄檔（雲端格式）<br/>timestamp, topic, payload"/]
  TR["time_range.py<br/>--from / --to 篩選（含頭不含尾）"]
  DE["device_events.py<br/>read_records → summarize<br/>造訪、跌倒警報、在線時段"]
  IN --> TR --> DE

  DE --> CG["caregiver.py<br/>caregiver_text：事件摘要、<br/>處置提示、照護紀錄草稿"]
  DE --> TREND["--trend：usage_trend<br/>近 7 天 vs 前 7 天<br/>（check_trend，用語規則同輸出檢查）"]
  DE --> ASK["event_ask.py（radar-ask）<br/>ask.py：提問 → 固定題號"]

  KGR["kg_rules.py（radar-kg-level）<br/>量測值 → 知識圖譜等級"] --> CG
  MAN[("kg_manifest.py<br/>雜湊與核准檢查")] -.-> KGR

  CG --> AUD{"audience.py<br/>讀者能看這份資料？"}
  AUD -- 否 --> STOP1["不產生文字"]
  AUD -- 是 --> RW["rewrite.py<br/>範本層 → 模型層"]
  LM["local_model.py<br/>Jetson 上的在地模型"] -. 改寫 .-> RW
  RW --> OC{"output_check.py<br/>數字都來自事實？<br/>無醫療用語、無「誤報」？<br/>斷線不寫「0 次」？"}
  TREND --> OC
  ASK --> OC
  OC -- 模型輸出沒過 --> FB["退回範本，記下原因"] --> OC
  OC -- 範本也沒過 --> STOP2["結束碼 1，不輸出"]
  OC -- 通過 --> OUT[/"JSON 給 Dashboard<br/>caregiver-report-v0<br/>usage-trend-v0<br/>event-ask-v0"/]

  classDef repo fill:#e3f1ee,stroke:#1d6b5f,color:#12302b
  classDef stop fill:#fbe9e7,stroke:#c0392b,color:#4a1510
  classDef pend fill:#fdf1e4,stroke:#d9822b,color:#4a2a08,stroke-dasharray:4 3
  class TR,DE,CG,TREND,ASK,KGR,MAN,AUD,RW,OC,FB repo
  class STOP1,STOP2 stop
  class LM pend
```

- 在地模型還沒接上真的型號（`06_Jetson硬體評估.md`），目前輸出都來自範本層。
- Demo 廁所沒有個人 ID，只出場域層級的報告；知識圖譜等級部分以人工輸入的量測值示範（換算規則卡在 E7，`09_換算規則草稿.md`）。
- 每段文字記下走哪一層（範本或哪一版模型），以及知識圖譜版本。
