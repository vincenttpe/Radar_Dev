# 目標架構（草案，待團隊確認）

## 本 repo 的範圍（2026-10-08 確認）

現有系統已經保存最近 7 天內的全部雷達資訊，目前只做簡單運用。本 repo 是從這個現況分出來的新分支，負責分析建議路徑中「知識圖譜對應」到「輸出文字」這一段：

1. 讀取現有系統保存的 7 天雷達資訊。資料放在另一個雲端，以 JSON 格式存取；欄位待確認（待確認事項第 1 項）。
2. 以在地模型把資訊對應到知識圖譜的指標與等級。
3. 依不同 Profile 輸出各自需要的文字訊息：狀態、建議等。Profile 先按下表五種規劃（2026-10-08 確認），內容細節待甲方與各讀者確認。

| Profile | 要看什麼 | 用語 |
|---|---|---|
| 居服員 | 每位長者近 7 天的狀態摘要、需注意的變化、今天可帶的活動 | 口語、可直接照做 |
| 醫師 | 各指標等級與 7 天趨勢、對應的知識圖譜依據與版本 | 專業用語、附數值 |
| 家屬 | 整體狀況、有沒有變差、在家可以怎麼陪伴 | 白話、避免嚇人也不淡化 |
| 長者本人 | 自己的狀況與鼓勵、今天建議做的運動 | 簡短、正向、國語或台語 |
| 主管機關 | 機構層級的統計與趨勢，不含個人資料 | 報表格式、去識別 |

同一份事實（等級、建議）只產生一次，五種 Profile 只是改寫與取捨，不會各自得到不同的等級。

雷達偵測、跌倒警示、7 天資料的保存都在現有系統，不在本 repo 範圍；本 repo 只讀資料、不改上游。

## 三個原則

1. **兩條路分開。** 跌倒警示走秒級的即時路徑，不經過知識圖譜、LLM 或報表伺服器；其他姿態判斷走分析路徑，產出日報與週報。分析路徑故障不影響警示。
2. **事實在上游決定。** 數值、分數、建議由規則與知識圖譜決定；在地 LLM 只負責依讀者改寫說法，不能新增或改動事實。
3. **每一筆都追得回來。** 同一個事件編號從雷達一路帶到 Dashboard，每一步記時間戳；每份輸出記下用了哪一版規則、知識圖譜與 Profile。

## 資料流

**即時警示路徑（只處理跌倒）**

雷達偵測 → 裝置判定跌倒 → 立即送出預警（斷網時本地警報）→ 裝置端語音確認（國語、台語；有限語句，不經雲端下指令）→ 通知閘道（含備援）升級或取消 → 居服員、家屬、機構按「已收到」，逾時自動升級

端到端延遲目標 2–3 秒（待確認事項第 3 項，2026-10-08 部分確認）。

**分析建議路徑（全部姿態）**

事件佇列（斷線暫存補傳）→ 格式檢查、去重、原始存檔 → 個人時序資料庫（以代號存）→ 規則評分（常模＋個人基線）→ 知識圖譜取建議 → 在地 LLM 依 Profile 改寫（失敗時改用範本）→ 輸出檢查（數字、用語、權限）→ Dashboard 與報表 → 現場回饋（誤報／屬實）→ 知識圖譜更新審核、去識別研究庫

## 知識圖譜的更新來源（2026-10-08 確認）

知識圖譜不是一次建好就不動，預期從多個方向更新，但因為內容與醫療行為相關，**不做全自動更新**：每一條變更都由人審核後才進版（審核人見待確認事項第 6 項）。

| 來源 | 方式 |
|---|---|
| 學術資料 | 把文獻的量表、常模、建議重新編碼成知識圖譜的指標、等級與建議 |
| 實際數據 | 現有系統累積的雷達資訊與現場回饋，用來檢視門檻、等級與建議是否合理，提出修改候選 |
| 現有 v1 | 舊雛形承接的 5 個指標，作為起點 |

無論來源，流程都是「提出候選 → 人審核 → 升版（v2、v3…）→ 舊版保留」。程式可以協助整理候選與比對差異，但不能自行寫入知識圖譜。

## 各元件職責

| 元件 | 職責 |
|---|---|
| 裝置（雷達＋小型語言模型） | 偵測姿態與跌倒；用語音向長者確認；只送結構化事件，不送文字或語音 |
| 警示服務 | 接收跌倒預警，多通道通知，追蹤「已收到」與逾時升級，監看裝置心跳 |
| 事件接收 | 格式檢查、去重、原始事件只追加不修改 |
| 評分 | 規則門檻對應知識圖譜的評分標準；記錄規則與圖譜版本 |
| 知識圖譜 | 只存知識（指標、等級、建議），不存個人資料；更新需審核（目前由公司審核，見待確認事項第 6 項） |
| 報告 | 組裝建議、依讀者 Profile 改寫、輸出前檢查 |
| Dashboard | 呈現警示、報告與甲方統計；收集現場回饋 |

## 建議順序

依上方「本 repo 的範圍」調整：

1. **先做（本 repo）：** 確認現有系統 7 天雷達資訊的 JSON 欄位（待確認事項第 1 項）；定義雷達資訊 → 知識圖譜指標與等級的對應規則與版本號；定義各 Profile 的輸出內容與格式；在地 LLM 改寫與範本備援；輸出檢查（數字、用語、權限）。
2. **接著（本 repo）：** 現場回饋；知識圖譜更新審核流程。
3. **現有系統或之後：** 事件格式版本化、警示路徑、訊息佇列與斷線補傳、時序資料庫、去識別研究庫（需同意書、IRB、資料使用協議）。
