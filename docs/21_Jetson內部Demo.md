# Jetson 內部 Demo（草案，2026-10-28）

在 Demo 機台（Orin NX 16GB，`docs/05` B1）上，**頁面、服務、在地模型都在同一台 Jetson**，畫面接在 Jetson 的螢幕上。目的是讓團隊先實際體會「打字提問、在地模型在這台 Jetson 上選題」，再決定對甲方 Demo 要怎麼演（`docs/11`）。只用模擬資料，內部使用。

## 架構

```
Jetson 螢幕
└─ 瀏覽器全螢幕開 http://127.0.0.1:8765/#replay
      │  打字提問：POST /api/ask（只送提問文字）
      ▼
demo/jetson_serve.py（Python 標準函式庫的 HTTP 服務，只聽 127.0.0.1）
  ├─ GET /           原型頁（和 demo/build.py 產生的相同，另外標記 Jetson 模式）
  ├─ POST /api/ask   event_ask.ask_events()：模型只選題號；答案是固定句型，通過輸出檢查
  └─ GET /api/stats  tegrastats 的最新一筆（GPU 使用率、記憶體、溫度）
      │
      ▼
Ollama gemma4:e4b（127.0.0.1:11434，GPU）
```

頁面和靜態原型頁（`demo/prototype.html`）是同一個範本，句子來源相同（`radar-caregiver`、`radar-ask --pick`）。Jetson 模式只多了：

- **打字提問接上模型**：先顯示「您是想問「……」嗎？」，按〔對〕才顯示答案，按〔不是〕或對不到時請讀者從選單點。確認句標出模型名稱、耗時與「在這台 Jetson 上執行」；答案旁註明「固定句型，不是模型寫的」。
- **對話泡泡**：提問與回覆依序排在輸入框下面，新的在最下方；對話框有固定高度，超過時在框內捲動，不帶著整頁跑。往下捲時輸入框固定在頂端橫幅下方（2026-10-29）。題目選單在對話框下面。打的字只留在畫面上，重播或重新整理就消失。
- **Jetson 狀態**：頂端橫幅顯示 GPU 使用率、記憶體與溫度（讀得到 `tegrastats` 時）。

不做的：追問（「那昨天呢？」）、一句問兩件事、時段解析。這些要擴充模型的回覆格式，屬於單向門「給讀者的輸出與用語」，題目與時段選項要先由審核人確認（`docs/06`「4.1」）。

## 交班重點（實驗，2026-10-29）

**只在 Jetson 內部 Demo 試用，不在 11 月對甲方的 Demo 主流程裡**（2026-10-29 決定）：`docs/11` 已決定 11 月 Demo 不用模型改寫，報告只用範本、在地模型只用在提問對應；理由是 Demo 機台上 `rewrite()` 被採用的文字仍有檢查抓不到的換詞（「設備」「走來走去」，[#35](https://github.com/vincenttpe/Radar_Dev/issues/35)；「設備」「我們」「他／她」後來已加進檢查，`caregiver-v2`）。這裡先讓團隊在 Jetson 上試、請居服員評比，結果再拿來決定之後要不要給甲方看。

目標是讓人感受在地模型的好處：**規則讓內容變豐富，模型讓語氣變口語**。事件摘要下方的〔比對：交班重點〕（另有〔比對：事件摘要〕，見第 4 點）：

1. **規則**（不經模型）：原句就是 PR #37 的【重點】加【事件摘要】（每次警報接它的結果，例如「08:32 語音詢問 10 秒未獲回應，30 秒後長者回覆沒事，警報解除」），前面加一行地點與時段（`caregiver.handover_text`）。不另寫句型（2026-10-29 決定）。
2. **在地模型**（`rewrite.rewrite_handover`，prompt `handover-v1`，2026-10-29 起和 `rewrite()` 共用「不能加範本沒有的時段詞、人稱與『設備』」）：只把【事件摘要】改寫成口語。第一行與【重點】由程式固定顯示：實測模型常把這兩行整行省掉，而【重點】的數字在事件摘要裡都還有，檢查擋不到。
3. **檢查**：和 `rewrite()` 同一道（數字都要在事實裡、範本的數字不能漏、「無法判斷」等提醒要保留、長度不超過 2 倍、用語，以及次數與時間長度整段比對，PR #41 起 `rewrite()` 也用），不能加範本沒有的時段詞、「我們」「他」「她」「設備」也共用（`caregiver-v2`），交班重點另加一項（時刻）：
   - 每個時刻都要出現（漏掉一件事時，它的時、分可能剛好在別處出現，只比數字會放過）；
   - （和 `rewrite()` 共用）次數與時間長度要整段對得上：「5 次」「1 筆」「22 分鐘」「3 分 10 秒」「1 小時 15 分」各算一組（「5 次」改成「6 次」時，5 還在「10:05」裡；「3 分 10 秒」改成「2 分 10 秒」時，只比「10 秒」會放過，2026-10-29 審查實測）；
   - 不能加上範本沒有的時段詞（「早上」「下午」……）、「我們」「他」「她」與「設備」（2026-10-29 起和 `rewrite()` 共用，`caregiver-v2`、`handover-v1`；「其他」不算「他」）。
   沒通過就維持原句，畫面寫出原因。
4. **畫面（測試版，2026-10-29 決定）**：事件摘要下方有〔比對：事件摘要〕〔比對：交班重點〕兩個按鈕，左邊「沒用模型（規則產生）」、右邊「用在地模型改寫」並排（手機上下排），讓人逐句對照。事件摘要整段交給 `rewrite()`；交班重點的前兩行（地點與時段、【重點】）固定在上。模型版標「在地模型改寫 · 模型 · 秒數 · 已比對數字與時刻；意思請對照原句」。**沒通過檢查的模型輸出也列出**，加刪除線並標「未採用（沒通過檢查，讀者看到的是左邊的原句）」，下方寫原因（2026-10-29 決定，方便評比模型實際寫了什麼）；這段文字只回給頁面，不寫進 log 或檔案。模型逾時、出錯或沒有輸出時寫「在地模型沒有回應」，和「沒通過檢查」分開；連不上服務時另外寫明；原句本身沒通過檢查（服務回 500）時整段都不顯示，只寫原因。沒有收到資料時兩種比對都不交給模型。重播時按鈕停用，等待中按了重播，晚回來的結果不會畫上去。
5. **沒有收到資料**：只顯示「沒有收到資料，無法判斷」與【重點】（請通知資訊人員），不交給模型。

2026-10-29 在雲端容器（CPU，Gemma 4 E4B Q4_K_M）實測，Demo 的模擬資料改寫一次約 40 秒、約 190 token；Demo 機台改寫時約 27.4 token／秒（`docs/06`「4.1」，2026-10-29），推估約 7 秒，待實測。

| 版本 | 結果 |
|---|---|
| 舊原句（事件逐條列出），沒有時段詞與「我們」的規則 | 口語程度高，但寫出「**下午** 10:03」（10:03 是上午）與「**我們**語音詢問」（問話的是裝置），數字檢查擋不到 |
| 舊原句，加上這條規則 | 3 次都採用、事實正確；把警報和解除併成一句、加「接著」「又」 |
| 新原句（【重點】＋事件摘要），【重點】交給模型 | 3 次都採用，但**每次都把【重點】整行省掉** |
| 新原句，第一行與【重點】固定（現行） | 3 次都採用、事實正確；加「時」「就」「有」「發生在」這類口語連接，例如「在線期間跌倒警報有 2 次：08:32 時語音詢問了 10 秒沒回應，30 秒後長者回覆沒事，警報就解除」 |

**2026-10-29 決定**：口語程度與準確度維持現行（準確優先，不加範本沒有的時段詞、「我們」「他」「她」「設備」）；句型與 prompt 照現行（`handover-v1`：詞表和 `rewrite()` 共用，PR 審查時決定）。句型、prompt 與檢查仍是草案，對甲方 Demo 或正式使用前要經審核人確認（單向門「給讀者的輸出與用語」）。

**已知限制（2026-10-29 審查找到，決定不再加檢查，靠並排對照與居服員評比找出來）**：
- 數量只比「有沒有出現」，不比屬於哪個事件：「主動呼救 1 次」改成「2 次」時，「2 次」在跌倒那行本來就有，會被採用；兩次警報的時間長度（「3 分 10 秒」「2 分 35 秒」）對調也一樣。
- 「沒有跌倒警報……」改成「有跌倒警報……」、或整句刪掉，沒有數字可比，會被採用。
- 換詞造成的意思偏移（例如「在線」寫成「正常運作」、#35 的「走來走去」、「警報解除」寫成「警報關掉」）。「設備」「我們」「他／她」已加進檢查。

`tests/test_handover.py` 用測試固定前兩項（REVIEW.md 3.5「已知問題用測試固定」）。所以模型版一定和原句並排顯示，不單獨出現。**Demo 前要做（2026-10-29 決定）**：請 1～2 位居服員看 10 份原句與口語版，記下哪個好懂、有沒有講錯；講錯的寫法補進檢查或 prompt。

## 安全

- 服務只聽 `127.0.0.1`，沒有改聽其他網卡的參數；同網段的電腦連不進來。
- 模型只能用 `--endpoint` 接本機的伺服器（127.0.0.1、localhost、::1），不接受 `--cmd`（任意指令可能把提問轉送到別台機器；2026-10-29 決定），提問不會送到區網上的其他機器。
- 讀者打的原文不寫進本服務的 log、不存檔：log 只記方法、路徑與狀態碼（`tests/test_jetson_serve.py` 檢查）。
- 畫面只寫得出能驗證的說法：「在這台 Jetson 上執行」「提問不寫進本服務的紀錄」。原本的「資料不出這台 Jetson」要等確認 Ollama 不記錄 prompt 之後才能恢復（2026-10-28 決定；見下方待核對）。
- 請求帶 `Origin` 而且不是這個頁面時拒絕（403），避免 Jetson 瀏覽器開著的其他網站借這個服務送提問。
- 這個服務把讀者打的字送進模型，屬於單向門「個人資料的流向」（`REVIEW.md` 第 2 節；`pr_gate.py` 的 `DOORS` 已列入）。
- Ollama 會不會記錄 prompt 要確認並關掉（`docs/20` 第 3 步）。

## 啟動步驟

前提：`docs/20` 第 1～3 步做完（Python 3.11 venv、`pip install -e .`、Ollama 在 GPU 上跑 `gemma4:e4b`）。

1. **先量一次準確率與延遲**。Gemma 4 在 Ollama 預設開著思維鏈，一定要加 `--reasoning-effort none`（2026-10-28 在 Demo 機台實測：關掉後每題約 0.4～0.5 秒，開著時約 8.7 秒，`docs/06`「4.1」）：

   ```bash
   radar-model-eval --endpoint http://127.0.0.1:11434/v1 --model gemma4:e4b --reasoning-effort none --event-questions
   ```

2. **啟動服務**（在 repo 根目錄、用 repo 的 venv）：

   ```bash
   python demo/jetson_serve.py --endpoint http://127.0.0.1:11434/v1 --model gemma4:e4b --reasoning-effort none
   ```

   啟動後馬上印出網址，頁面就能開；同時在背景問一題暖機，完成時印出「暖機完成：x.x 秒」（第一次載入模型要十幾秒）。印出「暖機失敗」時看後面的原因，常見的是 Ollama 沒開或模型名稱打錯；這時頁面仍能開，但打字提問會改請人從選單點。找不到 `tegrastats` 時只是不顯示 Jetson 狀態。`--port` 換埠號，`--no-warmup`、`--no-stats` 關掉暖機與狀態。

   還沒有模型伺服器、只想看頁面與流程時，用 `--echo` 試跑（不送出任何東西；打字提問一律對不到題目，改請人從選單點；`--no-warmup` 省掉一定會失敗的暖機）：

   ```bash
   python demo/jetson_serve.py --echo --no-warmup
   ```

3. **在 Jetson 的螢幕上開頁面**：Demo 機台有 Firefox（2026-10-28 確認）。用一個專用的設定檔開全螢幕（kiosk），按 Alt+F4 離開：

   ```bash
   mkdir -p ~/radar-demo-firefox
   firefox --kiosk --new-instance --profile ~/radar-demo-firefox http://127.0.0.1:8765/#replay
   ```

   - 用專用設定檔是因為 Firefox 已經開著時，`--kiosk` 只會在原本的視窗開新分頁，不會進全螢幕；專用設定檔也不會帶到平常瀏覽的分頁與書籤。
   - 設定檔目錄不要用 `.` 開頭：Ubuntu 22.04 的 Firefox 是 snap 版，讀不到家目錄裡的隱藏目錄（待核對）。
   - 第一次開可能會跳出歡迎頁或「設為預設瀏覽器」的詢問，先在這個設定檔裡關掉一次，展示時就不會再出現。

4. **展示**：按「下一個事件」重播完，再打字提問。建議的順序：
   1. 先點選單問一題，說明原本的做法；
   2. 打「有人跌到嗎」（故意打錯字），看確認句與耗時，按〔對〕；
   3. 打「斷線」這種只有兩個字的問法；
   4. 打「他今天血壓多少」，系統不回答醫療問題，改請人從選單點；
   5. 拔掉網路線再問一次，說明模型就在這台 Jetson 上。

## 頁面打不開時

Firefox 顯示「Unable to connect／無法連線」代表 `127.0.0.1:8765` 沒有服務在聽：

1. 看跑 `jetson_serve.py` 的終端機：有沒有印出「開啟 http://127.0.0.1:8765/#replay」。沒有的話看錯誤訊息（例如 `No such file or directory`：還沒切到有這個檔的分支或版本）。
2. 服務要一直開著：關掉那個終端機或按 Ctrl+C，服務就停了。瀏覽器要在**另一個**終端機開。
3. 確認埠有在聽：`ss -ltn | grep 8765`；或 `curl -s http://127.0.0.1:8765/ | head -c 80` 要看到 `<!doctype html>`。
