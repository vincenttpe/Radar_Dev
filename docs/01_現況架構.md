# 現況架構（舊雛形 Health-care-report-LLM）

依據：2026-10-06 取得的 zip，只讀、未實際執行。程式在 `legacy/prototype/`。

## 它在做什麼

輸入一串英文動作描述（每筆含 Timestamp、Motion、Speed，例如 "A person hop on one foot."），輸出一份繁體中文 Markdown 健康報告：每筆動作的類別、分數、運動建議，以及「本週建議運動」。

## 處理流程（`Project1.py` 的 `run_pipeline`）

```
英文動作描述（JSON）
  → 關鍵字規則分成 8 類
  → MiniLM 找最相似的標註句，沿用它的類別與分數
  → Neo4j 知識圖譜查建議（相似度 ≥ 0.70 才查）
  → DuckDuckGo 即時搜尋網頁補充內容
  → 套模板（Qwen2.5-0.5B 預設關閉）
  → 繁中 Markdown 報告
```

1. 讀 `data/samples/*.json`，依 `--start`/`--end` 時間範圍過濾、排序。
2. 把一句動作依 `->`、`then` 等切成片段。
3. 規則層 `detect_base_classes`：用關鍵字歸到 8 類（下肢肌力、單腳站立、心肺耐力、步行速度、來回行走、上肢與軀幹活動、空間方位位移、其他）。
4. 向量比對：`all-MiniLM-L6-v2` 把片段與 `data/labels/sorted_data.csv`（517 句，含 class 與 score 0–4）比相似度，取最像的一句，**直接沿用那一句的 class 與 score**。
5. 知識圖譜：相似度 ≥ 0.70 才用 (class, score) 查 `Metric → Criteria(score) → Suggestion`。
6. 外部搜尋：DuckDuckGo 搜健康與復健網頁，抓頁面文字、做片段檢索，補知識圖譜缺的內容。
7. LLM（選用）：`USE_LLM=1` 才載入 Qwen2.5-0.5B-Instruct 改寫；預設走固定模板。
8. 組成報告：「一、個別動作分析」「二、整體建議」與免責聲明。

## 已知問題

1. **分數不是量測值。** 報告的分數是最相似標註句的分數，同一句描述永遠拿同一個分數，與長者實際表現無關。
2. **標註資料不平衡。** 517 句裡單腳站立 1 句、步行速度 3 句、心肺耐力 9 句，空間方位位移 219 句。
3. **類別對不齊。** 分類有 8 類，知識圖譜只有 5 個指標。另外「步行速度」只有 4 個等級（沒有 4 分），其他指標都是 5 級。
4. **程式結構。** 全部邏輯在一個 5,386 行的檔案；14 個函式重複定義（例如 `ext_is_relevant_evidence` 5 次），實際生效的是最後一份；部分設定值在檔案中段被重新指定。模型與資料庫在 import 時就載入，沒有測試。
5. **外部搜尋。** 報告產生時即時抓網頁，結果每次可能不同，也有來源可靠度與使用條款的問題。
6. **依賴。** 原 `requirements.txt` 是 Jetson 整台機器的 pip freeze，其他機器裝不起來，也沒列 torch。
7. **README 不一致。** 寫著以 `uvicorn app:app` 啟動網頁版，但 zip 裡沒有 `app.py`。
8. **密碼。** 原 `build_embeddings.py` 寫死了一組 Neo4j 密碼（本 repo 已移除，見 `04_遷移紀錄.md`）。
