# 在地模型不用中國開發、或以中國模型為基底的模型

Jetson 上的在地模型（改寫、提問對應、照護紀錄、句庫起草），以及評估時拿來比較的模型，都不用中國開發的模型，也不用以它們為基底微調、蒸餾或量化的版本。例如 Qwen、DeepSeek（含 `deepseek-r1-distill-llama` 這類蒸餾版）、GLM／ChatGLM、百川、InternLM、MiniCPM、Yi、混元。

舊雛形用的 Qwen2.5-0.5B（`docs/01`、`legacy/`）只留作歷史紀錄，新系統不沿用。

## 怎麼執行

- **選型時**：每個候選模型都要看 model card，記下開發者、base model（一路追到最底層）與授權，寫進選型紀錄；base model 查不到的不用。
- **評估工具**：`radar-model-eval` 依模型名稱擋下常見的中國模型家族（`src/radar_agent/model_policy.py`），不送任何題目。名稱檢查只是提醒，改過名字的模型擋不住，最後仍以 model card 為準。
- **部署時**：Jetson 上實際載入的模型檔，名稱與雜湊要和選型紀錄一致（部署程式之後再做）。

不列入：Gemma 4 12B（2026-06 發表）在 Jetson AI Lab 標示要 16GB 記憶體、支援機種只列 Thor 與 AGX Orin 64GB（[模型頁](https://www.jetson-ai-lab.com/models/gemma4-12b)），Orin NX 16GB 放不下。

**Llama-Breeze2 待決定**：Breeze2 的語言模型以 Llama 為基底，但視覺部分用 InternViT-300M（上海人工智慧實驗室 InternVL 系列，[論文](https://arxiv.org/html/2501.13921v3)），Hugging Face 上的架構標為 `InternVLChatModel`。只用文字部分算不算「以中國模型為基底」，由人決定；決定前不從表中移除，也不改 `model_policy.py`。另外它是自訂的多模態架構，找不到現成可給 llama.cpp／Ollama 用的 GGUF。

**非台灣訓練的模型可能夾雜簡體字與大陸用語**，目前輸出檢查擋不下來，見 [#22](https://github.com/vincenttpe/Radar_Dev/issues/22)。

Orin Nano 8GB 上的公開速度：Llama 3.2 1B 約 45 token/s、Gemma 2 2B 約 26 token/s（[第三方比較](https://computingforgeeks.com/edge-llm-jetson-orin-vs-ai-hat-2-vs-hailo-10h/)，Ollama）；Gemma 3 4B 約 10 token/s（[NVIDIA 論壇使用者回報](https://forums.developer.nvidia.com/t/inference-time-for-gemma3-4b-on-jetson-origin-nano/339059)）。都是別人的數字，以 `radar-model-eval` 實測為準。

## 考慮過的做法

- **只限制部署、不限制評估**：評估時用中國模型當比較基準，數字會被拿去當選型理由；一併不用比較單純。

## 後果

- 台灣團隊以 Llama 為基底的繁體中文模型（Breeze2、TAIDE）是優先候選：有繁體中文續訓，基底也不是中國模型。
- 小模型的繁體中文與台語能力仍要實測；台語輸出（F6）若小模型做不到，維持範本或句庫。
- 授權條款（Llama、Gemma、TAIDE 各自不同）要在選型時確認是否允許商用與在機構現場部署（F2）。
