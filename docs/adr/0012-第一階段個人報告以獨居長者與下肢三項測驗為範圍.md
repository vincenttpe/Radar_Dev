# 第一階段的個人報告：獨居長者、指定測驗時段的下肢三項、專業輔助定位

目前的報告只寫地點、不寫是哪一位長者：Demo 是多人共用的廁所，雷達分不出進來的是誰（`docs/16`「不在這次對接」）。
知識圖譜的等級與建議要對到個人才有意義，但五項指標都是體適能測驗成績，現有的裝置事件換算不出來（`docs/09`、`docs/05` E7）。
2026-11-03 的討論（使用者提供的市場與研究參考，內容未逐一查證）提出一個可行的切入點，本篇把它記成**提議**：

1. **對象：獨居長者**。一台雷達只看一個人（2026-10-16 產品方向），「裝置 = 長者」直接成立，**不需要辨識身分**；同一個人可以跨日、跨週比較。
2. **指標：下肢三項，在指定的測驗時段由雷達量**，不從日常生活的動作推算。三項正好是知識圖譜 v1 的其中三項：

   | 測驗 | 知識圖譜 v1 的指標 | 現況 |
   |---|---|---|
   | 坐站測試（30 秒反覆起站） | 下肢肌力 | 沒有換算規則（`docs/05` K-1） |
   | 短距離步行 | 步行速度 | 只有模擬事件與草案規則（`demo/kg_build.py`） |
   | 起身—行走—轉身—坐下（2.44 公尺來回） | 來回行走 | 原本判定日常生活不會出現；在測驗時段可以量 |

   單腳站立、心肺耐力（2 分鐘原地抬腳）第一階段不做，照舊寫「無法評估」。
3. **定位：專業輔助**。系統整理量測結果與知識圖譜的等級，運動建議由專業人員（PT 等）選擇或核准；系統不推定病因、不自動調整處方。
   在地模型照舊只負責選題與改寫，不決定等級、禁忌或劑量（ADR 0002、0007）。

## 為什麼是這三項

- 以「次數、時間」為主的指標，比關節角度、精細骨架可靠：雷達偵測得到細微動作，不等於關節定位準確。
- 三項都是指定動作，開始與結束清楚，可以用碼表或影像當參考量測，逐項驗證誤差與重測變動。
- 這是建議的開發順序，**不是宣稱現有雷達就能可靠輸出這三項**；每一項都要先用本專案的雷達做對照驗證，驗證前報告不能宣稱準確度。

## 考慮過的做法

- **維持只寫地點、不做個人報告**：多人空間做不了個人報告，知識圖譜一直只能停在 Demo。
- **先做多人空間的個人報告**：要先解決辨識身分（是誰進來），雷達做不到，或要另外接門禁、手環等身分來源，範圍大很多。
- **五項一起做**：單腳站立、心肺耐力不在雷達擅長的範圍，會拖慢前三項。
- **從日常生活的動作推算（例如每天的起身次數）**：要另外定義替代指標與門檻（`docs/05` K-1、決策單 D-1），知識圖譜也要升版；可以之後再評估，不放在第一階段。
- **全自動產生個人化運動處方**：安全責任與醫材法規風險都高（下面「後果」），不做。

## 後果（如果改為 accepted）

- **辨識身分不是前提，但「裝置 ↔ 長者」的設定是**：安裝時建立對照表，換房、退住時更新（`docs/05` 4-9）。這是設定，不是辨識。
- **有人來訪的時段要另外處理**：居服員、家屬在場時，事件可能算到長者身上（`docs/05` 4-10）。先用簡單規則（例如測驗時段要確認只有長者一人、到訪時段不計入），規則另外定。
- **個人資料的範圍變大**：輸出對應到具名長者後，全部都是個人資料。讀者權限（`audience.py`）、Dashboard 上誰看得到、長期資料由誰保存（`docs/05` E8）都要重新確認，屬單向門「個人資料的流向」。
- **非醫療器材定位要重新檢視（ADR 0008）**：0008 目前靠「不使用醫療用語」把關，但只靠標示不夠，要看實際功能、預期用途與對外宣稱；知識圖譜 v1 的原文本來就有「跌倒風險極低」、建議量這類內容。
  個人報告上線前，先把預計的畫面、輸出句型、使用對象與宣稱交給醫材法規顧問評估，必要時向 TFDA 做屬性或分類諮詢（`docs/05` F11）。結果可能要另寫 ADR 取代 0008。
- **知識圖譜要補內容（v2）**：量測限制、運動的適用條件／禁忌／停止條件、規則的文獻依據（`docs/05` E9），屬單向門「知識圖譜內容」，由審核人提供。v1 的核准（K-2、E4–E6）仍是前提。
- **要先做驗證**：三項測驗各自和參考量測對照（收幾位長者、幾次、什麼情況要拒絕輸出），驗證計畫另外寫，要等雷達負責人回覆能輸出哪些事件（`docs/05` A45–A50、事件格式）。
