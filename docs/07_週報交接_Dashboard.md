# 甲方週報交接（給 Dashboard 團隊）

2026-10-12 決定：甲方週報（每週跌倒次數與活動量）由 Dashboard 處理，本 repo 不再產生週報。本 repo 只負責知識圖譜的等級判定，以及各 Profile 的文字或語音報告（`02_目標架構.md`「本 repo 的範圍」）。

本 repo 曾做過週報第 1 版（`radar-weekly-report`），已移除。這份文件整理當時定下的統計規則與踩過的問題，供 Dashboard 實作時參考。完整程式與測試可從 git 歷史取回：移除前最後一版在 commit `fa68bb8`（`src/radar_agent/weekly_report.py`、`tests/test_weekly_report.py`）。

規則都是**暫定值**，要等會議清單 C 類（`05_會議待詢問清單.md`）有答案後由 Dashboard 定案。

## 輸入

- 只支援「動作描述 JSON」（`Timestamp`／`Motion`／`Speed`／`fall`，樣本見 `data/samples_fall/`）。
- 裝置事件（`{"mode","event","trigger","userReply"}`）沒有時間戳，無法分到哪一天，所以沒有納入（會議清單 A1、A3、A4）。
- 時間格式：`2026/06/03 08:18 AM`，也接受 `-` 分隔與 24 小時制。樣本中有 24 小時制卻附 PM 的寫法（`17:31 PM`），小時大於 12 時忽略 AM/PM。
- 時間戳是本地時間、沒有時區，照原樣分到日曆日，跨日以 00:00 為界（會議清單 A4）。
- `fall` 欄位：`yes`、`true`、`1` 算是；`no`、`false`、`0` 算否（不分大小寫）。沒有欄位或其他值都算**無法判讀**，原值要保留下來。

## 統計口徑

| 項目 | 第 1 版的定義 | 待確認 |
|---|---|---|
| 一週 | 從指定起始日 00:00 起連續 7 天，不含第 8 天 00:00；預設為最新一筆所在週的星期一 | C3 |
| 跌倒次數 | `fall` 為是的筆數；裝置事件的 fall 與語音確認結果尚未納入 | C2 |
| 活動量 | `fall` 為否的筆數。跌倒那一筆不算；無法判讀是否為跌倒的紀錄也不算，另外列出筆數 | C1 |
| 對象 | 資料沒有長者或裝置代號，整份輸入視為同一個對象 | A5 |

活動量只是「紀錄筆數」。沒有動作持續時間，算不出「動了多久」（A6）；事件重送會灌水、漏傳會低估（A11）。

## 必須守住的原則

1. **沒有資料不等於 0。**
   - 整週沒有紀錄，或沒有一筆可判讀時，要寫「無法判斷是否發生跌倒」，不能寫 0 次。
   - 逐日表格的 0 只代表「該日沒有納入活動統計的紀錄」：可能沒收到資料，也可能只收到跌倒或無法判讀的紀錄。在拿到裝置在線時段之前（D3），不能寫成「沒有活動」或「沒有收到紀錄」。
2. **輸入的紀錄都可判讀，也不能寫成全週結論。** 沒有裝置在線時段，只能寫「本次輸入的紀錄中，跌倒標記共 N 筆」，不能寫「本週跌倒 N 次」。
3. **有任何一筆無法判讀，總數就只是下限。** 包括 `fall` 缺漏、`fall` 值無法辨識、時間無法解析。這時要寫「全週總數無法確認」，並依原因分開列出筆數。
4. **時間無法解析的紀錄，保守視為可能屬於本週。** 如果它標記為跌倒或 `fall` 值無法辨識，要逐筆列出，請人工確認。
5. **無法判讀的紀錄不丟棄也不猜。** `fall` 值無法辨識的那筆，在跌倒一節逐筆列出原值（可能就是跌倒），活動量也不能把它當成一般動作。
6. **本週之外的跌倒要列出來。** 不計入本週，但要逐筆列出，避免週起始日選錯時被埋掉。週起始日選錯導致本週沒有任何紀錄時，要提示「輸入資料有 N 筆在本週之外，請確認週起始日」。
7. **統計口徑要印在報告裡。** 上表的定義隨報告附上，避免數字被誤讀。

## 踩過的問題

- **同一個數字不要算兩次。** 第 1 版的 JSON 與 Markdown 曾各自計算「無法判讀」的筆數：JSON 不含時間無法解析的紀錄，Markdown 含，同一份週報寫出 1 和 2 兩個數字。修正方式是所有數字都在統計段算好，各種輸出只讀欄位，並用測試檢查每種輸出的數字都相同（`test_every_number_in_markdown_matches_the_json`）。
- **標籤要和實際算法一致。** 「有紀錄的天數」實際上只算有動作紀錄的日子，只收到跌倒或無法判讀紀錄的日子沒算進去，後來改成「有動作紀錄的天數」。
- **說明文字也是口徑。** 逐日表格下的說明曾寫成「0 表示當天沒有收到紀錄」，與實際算法不符，後來改正。給甲方讀的每一句話都要對得上程式實際怎麼算。
- **最忙的一天並列時**，第 1 版取最早的那一天；要不要並列全列，待甲方決定。
