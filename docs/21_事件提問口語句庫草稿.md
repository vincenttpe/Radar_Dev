# 事件提問口語句庫草稿（送審用）

**狀態**：草案，AI 起草（2026-10-28），**尚未審核，程式沒有套用**。審核分工見決策單 E1；核准後才改 `src/radar_agent/caregiver.py`（或另開句庫檔）與 `event_ask.py`。

## 為什麼要另寫一份

事件提問（`radar-ask`，`docs/11`）在 Jetson 測試可以跑了，但答案沿用【事件摘要】的固定句型，例如「在線期間跌倒警報 2 次（08:32、09:16）。」，資訊對，讀起來像報表。這份草稿把六題的答案改成口語說法，**事實與數字不變**，執行時仍是查表、填欄位，不經過模型（ADR 0002 的句庫做法）。

**範圍**：事件提問六題的答案句子，讀者是照護人員。題目文字、【事件摘要】、【處置提示】與家屬版用語（`docs/18`）不在範圍內。同屬單向門「給讀者的輸出與用語」（REVIEW.md 第 2 節），要先審後上線。

## 起草原則

1. **事實只來自 `Summary`**：每個欄位都對到現在答案已經寫出的事實，不新增數字。不寫「共 8 則」這類事實裡沒有的總數。
2. **警報不等於事件**：寫「有 2 次跌倒警報」，不寫「有人跌倒 2 次」。答案開頭不先回「有，」：「有沒有人跌倒？」回「有」會被讀成真的有人跌倒。
3. **不知道就說不知道**：斷線時次數前面一律加「在線期間」；斷線時段寫「系統無法判斷」。沒有資料時不回「沒有」。
4. **不多加建議**（ADR 0002 的 D-4）：處置提示原文照搬，不另加「要去看一下」「每 N 小時巡視」這類句子。
5. **非醫療用語**（ADR 0008）：不用診斷、治療等詞；「語音回覆沒事」不寫成誤報（C2）。
6. **沒發生的事仍寫「0 次」**：跟 `docs/11` 2026-10-19 的決定一致，輸出檢查靠這個寫法抓斷線時漏寫「在線期間」。要不要改成「沒有……」見待決 1。

## 共用句子

## 六題的答案

「有」是有事件時，「0」是沒發生時；斷線時「有」「0」兩句前面都加「在線期間」。

| 題目 | 情況 | 現在 | 草案 |
|---|---|---|---|
| 有沒有人跌倒？ | 有 | 跌倒警報 2 次（08:32、09:16）。 | 有 2 次跌倒警報，分別在 08:32、09:16。（只有 1 次時：有 1 次跌倒警報，在 08:32。） |
| | 0 | 跌倒警報 0 次。 | 跌倒警報 0 次。 |
| | 語音回覆沒事 | 語音回覆沒事 1 次。 | 長者用語音回覆「沒事」的有 1 次。 |
| | 另有主動呼救 | 另有主動呼救 1 次（10:03）。 | 另外還有主動呼救 1 次（10:03），這個不算在跌倒警報裡。 |
| 有沒有人主動呼救？ | 有 | 主動呼救 1 次（10:03）。 | 有 1 次主動呼救，在 10:03。 |
| | 0 | 主動呼救 0 次。 | 主動呼救 0 次。 |
| 有沒有人待太久？久待警報有幾次？ | 有 | 久待警報 1 次（10:45）。 | 有 1 次久待警報，在 10:45。久待警報是指有人停留超過裝置設定的時間。 |
| | 0 | 久待警報 0 次。 | 久待警報 0 次。 |
| 用了幾次？最久待多久？ | 有 | 有人使用 5 次，最長一次 22 分鐘。 | 一共有人用了 5 次，最久的一次待了 22 分鐘。 |
| | 0 | 沒有偵測到有人使用。 | 都沒有偵測到有人使用。 |
| | 使用途中斷線 | 另有 1 次使用途中裝置斷線，停留時間不明。 | 另外有 1 次是用到一半裝置斷線，不知道待了多久。 |
| | 資料結束時有人 | 資料結束時仍有人在內（10:50 起）。 | 資料最後一筆的時候還有人在裡面，是 10:50 進去的。（要不要加提醒見待決 3） |
| 裝置有沒有斷線？ | 有 | （直接列 C3、C4） | 有斷線：＋逐行列 C3、C4 |
| | 沒有 | 這段時間裝置都在線。 | 裝置都有連線，沒有斷線。 |
| 有哪些警報？要怎麼處理？ | 有 | 警報與處置提示：＋逐行 | 的警報和處理提示，照時間排：＋逐行（**每行處置提示原文不改**，原則 4） |
| | 沒有 | 這段時間沒有警報。／在線期間沒有警報。 | 沒有任何警報。／在線期間沒有任何警報。 |

「久待警報是指……」那句只在有久待警報時出現，用來解釋工程詞；不寫設定的分鐘數，因為那個數字不在 `Summary` 裡。

## 範例（Demo 模擬資料，`data/samples_demo/bathroom_morning.jsonl`）

有斷線（11:10–11:25）的版本：

```
有沒有人跌倒？
1 號廁所在 10/14 08:00–11:59 這段時間，在線期間有 2 次跌倒警報，分別在 08:32、09:16。
長者用語音回覆「沒事」的有 1 次。
11:10–11:25 裝置斷線，這段時間有沒有跌倒，系統無法判斷。
另外還有主動呼救 1 次（10:03），這個不算在跌倒警報裡。

有沒有人待太久？久待警報有幾次？
1 號廁所在 10/14 08:00–11:59 這段時間，在線期間有 1 次久待警報，在 10:45。
久待警報是指有人停留超過裝置設定的時間。
11:10–11:25 裝置斷線，這段時間有沒有人待太久，系統無法判斷。

用了幾次？最久待多久？
1 號廁所在 10/14 08:00–11:59 這段時間，一共有人用了 5 次，最久的一次待了 22 分鐘。
11:10–11:25 裝置斷線，這段時間有多少人使用，系統無法判斷。
```

沒有事件的版本（只取 08:00–08:29）：

```
1 號廁所在 10/14 08:00–08:29 這段時間，跌倒警報 0 次。
1 號廁所在 10/14 08:00–08:29 這段時間，裝置都有連線，沒有斷線。
1 號廁所在 10/14 08:00–08:29 這段時間，沒有任何警報。
```

## 待決

1. **0 次的說法**：A（草案）維持「跌倒警報 0 次」；B 改成較口語的「沒有收到跌倒警報」。選 B 要同時改 `output_check.py`：目前的檢查只抓「跌倒警報 0 次」，「沒有跌倒警報」在斷線時漏寫「在線期間」也會通過（2026-10-28 實測）。`output_check.py` 本身也是單向門。
2. **「在線期間」要不要換說法**：例如「裝置有連線的時間裡」。照護人員看得懂「在線期間」的話建議不換；要換也要一起改輸出檢查。
3. **資料結束時有人在內要不要加提醒**：例如「可能要去看一下」。這是新的處置建議，依原則 4 草案沒有加；要加的話請審核人決定句子。
4. **誰核准**：決策單 E1 還沒定。
