## E7：體適能指標怎麼量

知識圖譜的五項指標（下肢肌力、單腳站立、來回行走、心肺耐力、步行速度）都是測驗成績。`09_換算規則草稿.md` 判定：**現有的裝置事件與描述句，五項都換算不出來**（缺次數、距離、秒以下時間）。

| | 選項 | 影響 |
|---|---|---|
| ☐ a | 人工施測後輸入 | 不需要換算規則，`radar-kg-level` 已可用；要做輸入介面、決定誰輸入、怎麼對應長者代號，會碰到「個人資料的流向」 |
| ☐ b | 雷達在測驗時段量測 | 雷達端要送出逐次事件（例如每次坐→站的時間點）、測驗開始與結束標記，時間精度 10～20 Hz（A6、A7、A12）；換算規則照草稿「若由雷達在測驗時段量測」一節發展 |
| ☐ c（建議） | 先 a，b 當研究並行 | Demo 與第一版報告用人工輸入；雷達量測的資料累積後，再和人工成績比對準確度 |

**現在怎麼做**：五項都判為「雷達量不到」，不出等級。
**決定後要改什麼**：a／c → 設計輸入格式與介面；b／c → 請雷達負責人確認能送出哪些事件、時間精度多少。

## E2：量不到的指標怎麼呈現

| | 選項 | 影響 |
|---|---|---|
| ☐ a | 寫「本週無法評估」 | 讀者知道這一項存在但沒資料；五項都量不到時，報告會出現五行「無法評估」 |
| ☐ b | 不列 | 報告乾淨；但讀者可能以為這一項沒問題 |
| ☐ c（建議） | 依 Profile 不同：醫師與居服員看得到「無法評估」，家屬與長者本人不列 | 專業讀者知道缺什麼，一般讀者不被大量「無法評估」干擾 |

**現在怎麼做**：居服員範本寫「目前無法評估，已交由審核人確認」（`caregiver.py`）。
**決定後要改什麼**：各 Profile 的範本；`rewrite.py` 的必留提醒清單（目前「無法評估」改寫時一定要保留）。

## D-1：要不要定義日常生活替代量

測驗成績量不到，但雷達可以觀察日常生活，例如每日坐→站次數、每日行走時段數。這些**不能套用現有五項的門檻**（門檻是測驗常模），要當新指標另訂門檻。

| | 選項 | 影響 |
|---|---|---|
| ☐ a | 不做，只用測驗成績 | 範圍最小；雷達資料只用於場域摘要與跌倒、久待 |
| ☐ b | 做，先列候選指標送審核人 | 需要新的知識圖譜內容（門檻與建議）、審核（E1），以及雷達能辨識坐、站、行走（E3） |

**現在怎麼做**：沒有替代指標。
**決定後要改什麼**：b → 列候選指標與資料需求，送審核人；知識圖譜升版。

## F4：讀者與長者怎麼對應

讀者權限目前只分到「哪種 Profile 能看場域資料、哪種能看個人資料」（`audience.py`），還沒有「這位家屬只能看自己的長輩」。

| | 選項 | 影響 |
|---|---|---|
| ☐ a（建議） | 本 repo 只產生以代號標記的報告；登入、讀者與長者的對應、姓名套入都由 Dashboard 負責 | 本 repo 不保存讀者名單與姓名，個人資料範圍最小（與 A15 一致） |
| ☐ b | 本 repo 保存讀者與長者的對照表，產生時就過濾 | 本 repo 要負責這份名單的保護與更新 |

**也要決定**：家屬與長者本人用什麼管道收（Dashboard、App、LINE、簡訊、紙本），會影響文字長度與格式。
**決定後要改什麼**：知識圖譜等級結果要加上 `subject_id`；a → 輸出格式交給 Dashboard（B4）；b → 新增對照表與過濾。

## F7：現場回饋從哪裡進來

現場回饋（這次警報是誤報還是屬實、建議有沒有用）是第 2 步，也是之後校正規則與知識圖譜的依據。

| | 選項 | 影響 |
|---|---|---|
| ☐ a（建議） | Dashboard 收集，定期匯出給本 repo | 居服員只用一個介面；本 repo 只需定義匯入格式 |
| ☐ b | 本 repo 另外提供輸入介面 | 居服員要多學一個介面 |

**也要決定**：回饋要對到哪一筆事件（事件目前沒有編號，A11）、誰有權標「誤報」。注意 C2：語音回覆「沒事」不直接算誤報。

## D-2：紀錄檔有一行壞掉時

`radar-caregiver` 讀紀錄檔時，有一行不是 JSON 或不是物件，目前**整份拒收**並指出第幾行。欄位讀不懂的紀錄則照常列為「無法判讀」。

| | 選項 | 影響 |
|---|---|---|
| ☐ a | 維持整份拒收 | 不會默默略過資料；但七天的大檔壞一行就整份產生不出摘要 |
| ☐ b | 整行讀不懂的也算進「無法判讀」筆數，照樣輸出 | 報告照常產生，並寫出有幾筆讀不懂、請通知資訊人員 |

## D-3：地點名稱含醫療用詞時

輸出檢查不允許出現「診斷、治療、處方、保證」（非醫療器材定位）。地點名稱也會被檢查，所以地點叫「治療室」時整段摘要被擋下、不輸出。

| | 選項 | 影響 |
|---|---|---|
| ☐ a | 維持：地點名稱也檢查 | 現場要改用其他稱呼（例如「復健室」）|
| ☐ b | 地點名稱不檢查用語，其餘文字照檢查 | 地點照實寫；要確保地點名稱只來自設定，不來自模型 |

## D-4：在地模型改寫要檢查到多嚴

模型的改寫目前要通過：沒有多出來的數字、沒有醫療用詞、沒有漏掉範本裡的數字與「無法判斷」等提醒、知識圖譜原文一字不改、長度不超過範本 2 倍。沒過就退回範本。

**擋不到的情況**：數字都在但對應錯，例如把「跌倒 1 次、久待 0 次」寫成「跌倒 0 次、久待 1 次」。

| | 選項 | 影響 |
|---|---|---|
| ☐ a | 接受現況，定期人工抽查模型輸出 | 程式簡單；抽查頻率要訂 |
| ☐ b | 加嚴：數字要出現在同一個詞旁邊（例如「跌倒」後面接的數字要和範本相同） | 擋得住對調；模型改寫的自由度變小，退回範本的比例會變高 |
| ☐ c | 只讓模型改寫前後的串場句，事實句一律照範本 | 最安全；改寫的效果有限 |

**也要決定**：長度上限 2 倍是否合適。

## D-5：讀者權限表是否符合現場預期

照 `02_目標架構.md`「輸出的對象：場域與個人」寫成程式：

| Profile | 場域資料（沒有個人 ID） | 個人資料 |
|---|---|---|
| 居服員 | 可以 | 可以 |
| 醫師、家屬、長者本人 | 不可以 | 可以 |
| 主管機關 | 可以 | 不可以 |

| | 選項 |
|---|---|
| ☐ a | 照表 |
| ☐ b | 要調整（請寫明哪一格、為什麼）：＿＿＿＿＿＿＿＿ |

特別請確認：居服員能看個人資料（老人公寓）；醫師、家屬、長者本人看不到場域資料，例如 Demo 廁所的使用紀錄。
