# 跌倒警報處理流程（參考草案，2026-10-30）

給機構訂定正式流程時參考。**本文件不是機構的正式 SOP**：到場時限、通報對象、到場後的照護處置都由機構訂定，本文件只留空格與選項（第七節）。

依 `docs/adr/0008`，本系統定位為非醫療器材軟體，所以本文件只寫「誰、什麼時候、做什麼、找誰」，**不含任何醫療判定**（例如評估傷勢、量測、是否移動長者、照護處置）；照護人員到場後的處置一律依機構規定、由機構指定的人員負責。

雷達的警報是照護輔助資訊：有警報不代表一定發生跌倒，沒有警報也不代表沒有跌倒。

## 一、兩條路徑：即時警示與處置提示

- **即時警示**（第二到五節的依據）：裝置判定、本地警報、語音確認、雲端通知照護人員，都在現有系統，不經過本 repo（`docs/adr/0006`）。照護人員依即時警示處理。
- **處置提示**：本 repo 在分析路徑上事後產生的報告內容（`caregiver.event_notes`，Dashboard 依 `NOTE_KINDS` 分等級），用來回顧與交班，不能取代即時警示。

處置提示的每一句對到本文件的哪一節（句子和 `caregiver.NOTE_KINDS` 逐字相同，`tests/test_caregiver.py` 會比對）：

| 處置提示 | 等級 | 本文件 |
|---|---|---|
| 長者回覆需要協助，請立即到場。 | urgent | 二-B |
| 請立即到場確認。 | urgent | 二-C（語音詢問未獲回應；資料不在規格內、分不出是哪一種跌倒警報時也是這句） |
| 長者主動呼救，請立即到場。 | urgent | 三 |
| 長者回覆沒事，警報已解除；可視情況前往關心。 | resolved | 二-A |
| 已偵測到起身，警報已解除。 | resolved | 二-D |
| 停留超過設定時間，請前往查看。 | check | 四 |
| 這段時間無法判斷是否有跌倒，請通知資訊人員。 | device | 五 |

## 二、跌倒警報

裝置偵測到疑似跌倒時會用語音詢問長者（`docs/05` A34）。跌倒警報是在語音詢問之前還是之後送出，還在等雷達負責人確認（`docs/05` D1），所以照護人員收到警報時，語音詢問的結果可能還沒出來。照護人員看警報上的地點、時間，以及語音詢問的結果（有的話），依結果處理；結果還沒出來時，照 C 處理。

**A. 長者回覆沒事（警報已解除）**
- 回覆沒事不代表沒有跌倒（`docs/05` C2）。
- 是否到場、多久內到場：**由機構決定**（第七節第 1 項）。
- 到場時有任何不確定，改照 B 處理。

**B. 長者回覆需要協助**
- 立即到場。
- 依機構規定通報指定的人員（＿＿＿＿）。
- 指定的人員到場前，依機構規定陪同長者。

**C. 語音詢問沒有回應**
- 立即到場，同時依機構規定通報指定的人員（＿＿＿＿）。
- 進門前先出聲告知；進入浴廁等私密空間的方式依機構規定。

**D. 偵測到起身（警報已解除）**
- 這項解除功能目前關閉（`docs/05` A3、A34）。依 A34，10 秒內偵測到起身就解除、不送跌倒警報；收到跌倒警報之後還會不會再有起身解除，待雷達負責人確認（`docs/05` A26、issue #38）。
- 是否到場：**由機構決定**（第七節第 1 項）。
- 到場時有任何不確定，改照 B 處理。

## 三、主動呼救

- 長者主動呼救不一定是跌倒（`docs/05` C2），一律比照二-B 處理。
- 呼救之後可能也會收到「回覆沒事」或「偵測到起身」的解除（本 repo 依 `docs/05` A26 推定的配對，待雷達負責人確認，issue #38）；是否仍要到場，和二-A、二-D 一樣由機構決定（第七節第 1 項）。

## 四、久待警報

1. 前往查看，到場先出聲詢問。
2. 沒有回應或有任何不確定，改照二-C 處理。

## 五、裝置斷線

- 斷線期間雲端收不到這台裝置的資料，本 repo **無法判斷**是否有跌倒，照護人員可能收不到警示通知；裝置的本地警報是否照常運作，待雷達負責人確認。
- 照護人員怎麼即時得知裝置斷線（處置提示是事後產生的），待機構與雲端負責人決定（第七節第 6 項）。
- 斷線期間該地點改由人工巡視，頻率依機構規定（＿＿分鐘一次）。
- 通知資訊人員處理裝置。

## 六、事後記錄

- 記下：警報時間、到場時間、通報時間與對象、警報解除時間。
- 系統產生的照護紀錄草稿、事件摘要與交班重點都是輔助資訊，**不是機構的正式紀錄**；正式紀錄依機構表單填寫。
- 誤報（有警報、現場沒有事件）與漏報（現場有事件、沒有警報）記下來回報資訊人員，作為調整裝置設定的依據。

## 七、須由機構訂定的項目

| # | 項目 | 選項 |
|---|---|---|
| 1 | 警報已解除（回覆沒事、偵測到起身，含主動呼救之後的解除）時要不要到場 | ① 一律到場確認，時限＿＿分鐘 ② 由照護人員視情況決定（目前處置提示的寫法：回覆沒事是「可視情況前往關心」，起身解除只寫「警報已解除」） ③ 其他：＿＿ |
| 2 | 各情況的到場時限（二-B、二-C、三、四） | 由機構填寫：＿＿分鐘 |
| 3 | 通報對象與聯絡方式（含夜間、假日） | 由機構填寫 |
| 4 | 到場後的照護處置 | 由機構指定的人員訂定，本文件不涵蓋 |
| 5 | 進入浴廁等私密空間的規定 | 由機構填寫 |
| 6 | 裝置斷線時怎麼即時通知照護人員，以及斷線期間的人工巡視頻率 | 由機構與雲端負責人決定；巡視：＿＿分鐘一次 |

目前系統不改（2026-10-31 決定）：第 1 項由機構決定前，處置提示維持「可視情況前往關心」。機構選 ① 時，這句要另開 PR 修改，屬單向門「給讀者的輸出與用語」，並同步 `caregiver.NOTE_KINDS`、Dashboard（`docs/16`）與本文件第一節。

- 收到跌倒警報後還會不會有起身或回覆沒事的解除，以及解除配到哪一筆警報（`docs/05` A34、issue #38）：確認後改寫二-D 與第三節。
- 斷線時裝置的本地警報是否照常運作（雷達負責人），以及照護人員怎麼即時得知斷線（機構、雲端負責人）：確認後改寫第五節。
